================================================================================
                    المرحلة 7: المواد التشغيلية
================================================================================

📋 نظرة عامة:
--------------
المواد التشغيلية هي مواد تُشترى وتُستهلك داخلياً في المتجر —
لا تُباع للعميل مباشرة، لكن لها تكلفة حقيقية تؤثر على حسابات المتجر.

أمثلة: أكياس، كحول، علب، فتائل، فحم، ملصقات، ...

📌 القرار التصميمي:
   نفس جدول products — لا جداول إضافية.
   الفرق الوحيد: حقل is_operational = true في جدول categories.

📌 لماذا هذا القرار؟
   ✅ نفس نظام المشتريات يعمل بدون أي تعديل
   ✅ المخزون يُضاف تلقائياً عند الشراء (stock += quantity)
   ✅ تاريخ الشراء والتكلفة محفوظ في purchase_items
   ✅ لا جداول زائدة، لا تعقيد إضافي

📌 طبيعة المخزون هنا:
   stock ≠ الكمية المتبقية الفعلية
   stock = الكمية المشتراة الإجمالية (تراكمية)
   الاستهلاك لا يُسجَّل تلقائياً — هذه المواد تنفذ مع الوقت
   بدون تسجيل في منظومة البيع.
   الهدف الأساسي: تتبع التكلفة التشغيلية، ليس إدارة المخزون الدقيق.


================================================================================
                    🗂️ التعديل على الجداول الموجودة
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ جدول categories — إضافة حقل is_operational                                │
└─────────────────────────────────────────────────────────────────────────────┘

الحقل الجديد:
   is_operational    BOOLEAN    FALSE    هل هذا التصنيف تشغيلي؟

📌 القاعدة:
   is_operational = FALSE → منتج قابل للبيع (عطور، بخور، وشق، ...)
   is_operational = TRUE  → مادة تشغيلية (أكياس، كحول، علب، ...)

📌 التأثير على باقي النظام:
   - صفحة البيع (/invoices/create): تُفلتر المنتجات التشغيلية ولا تظهر
   - صفحة المشتريات (/purchases/create): تظهر جميع المنتجات بما فيها التشغيلية
   - المخزون: يزيد عند الشراء كأي منتج عادي

📌 Migration:
   ALTER TABLE categories ADD COLUMN is_operational BOOLEAN DEFAULT FALSE;

📌 أمثلة بعد التعديل:

   ┌──────────────────┬──────┬────────────────┐
   │ name             │ unit │ is_operational │
   ├──────────────────┼──────┼────────────────┤
   │ عطور زيتية       │ ml   │ FALSE          │
   │ عطور أصلية       │ ml   │ FALSE          │
   │ بخور             │ pcs  │ FALSE          │
   │ وشق              │ g    │ FALSE          │
   │ مبخرة            │ pcs  │ FALSE          │
   │ مستلزمات تشغيلية │ pcs  │ TRUE           │
   └──────────────────┴──────┴────────────────┘


================================================================================
                    📦 مسار إضافة مادة تشغيلية
================================================================================

   1. إنشاء تصنيف "مستلزمات تشغيلية" (is_operational = TRUE)
      أو أي تصنيف آخر بنفس الخاصية (مثل: مواد تعبئة، مواد تنظيف، ...)
         ↓
   2. إضافة المنتج في صفحة /products
      selling_type = 'unit_priced'
      category = مستلزمات تشغيلية
      price_tier_id = NULL
         ↓
   3. إضافة سعر في product_prices (اختياري — لأنها لا تُباع)
      يمكن تركه NULL أو وضع سعر تكلفة للمرجعية
         ↓
   4. الشراء عبر /purchases/create كأي منتج عادي
      stock += quantity تلقائياً


================================================================================
                    🔄 التأثير على صفحة البيع
================================================================================

📌 في /invoices/create (POS):
   عند جلب المنتجات من الـ backend:

   Product::with([...])->whereHas('category', function($q) {
       $q->where('is_operational', false);
   })->orderBy('name')->get();

   → المواد التشغيلية لا تظهر في قائمة المنتجات عند البيع
   → لا يمكن بيعها للعميل بالخطأ


================================================================================
                    🔄 خطوات التنفيذ (بالترتيب)
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 1: Migration — إضافة is_operational لجدول categories               │
└─────────────────────────────────────────────────────────────────────────────┘

php artisan make:migration add_is_operational_to_categories_table

Schema::table('categories', function (Blueprint $table) {
    $table->boolean('is_operational')->default(false)->after('unit');
});


┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 2: تحديث Model Category                                             │
└─────────────────────────────────────────────────────────────────────────────┘

إضافة 'is_operational' في $fillable و $casts:
   'is_operational' => 'boolean'


┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 3: تحديث صفحة التصنيفات (/categories)                              │
└─────────────────────────────────────────────────────────────────────────────┘

إضافة toggle لـ is_operational عند إضافة أو تعديل تصنيف.
عرض badge "تشغيلي" بجانب التصنيفات التشغيلية في القائمة.


┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 4: فلترة المنتجات في صفحة البيع                                    │
└─────────────────────────────────────────────────────────────────────────────┘

في InvoiceController@create:
   تعديل query المنتجات لاستثناء is_operational = true


┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 5: Seeder — إضافة تصنيف "مستلزمات تشغيلية"                        │
└─────────────────────────────────────────────────────────────────────────────┘

Category::firstOrCreate(
    ['name' => 'مستلزمات تشغيلية'],
    ['unit' => 'pcs', 'is_operational' => true]
);


================================================================================
                        ⚠️ قواعد العمل المهمة
================================================================================

1. ✅ is_operational = TRUE  → لا تظهر في صفحة البيع
2. ✅ is_operational = TRUE  → تظهر في صفحة المشتريات كأي منتج
3. ✅ stock هنا = كمية مشتراة إجمالية (تراكمية) — ليس المتبقي الفعلي
4. ✅ يمكن إنشاء أكثر من تصنيف تشغيلي (مواد تعبئة، مواد تنظيف، ...)
5. ✅ selling_type = 'unit_priced' دائماً للمواد التشغيلية
6. ✅ product_prices اختياري — لأنها لا تُباع
7. ✅ نفس نظام المشتريات يعمل بدون أي تعديل
