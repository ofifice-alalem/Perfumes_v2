## 1. الهيكل العام وآلية عمل مجلد `dist/`

مجلد `dist/` هو الناتج النهائي لعملية البناء والتجميع. يحتوي على كل ما يلزم لتشغيل المنظومة على بيئة Windows دون الحاجة للإنترنت:

```text
Perfumes_v2/dist/
├── منظومة السحابة Setup 1.0.0.exe      # برنامج التثبيت الرئيسي المعتمد (NSIS Installer)
├── server_payload/                     # حزمة السيرفر المحمولة الكاملة (Unpacked)
│   ├── php/                            # مفسر PHP 8.4 المحمول بكامل الملحقات (Extensions)
│   ├── apache/                         # خادم Apache 2.4 مع محرك SSL و mkcert
│   └── server/                         # نواة Laravel كاملة مع Vendor و Routes و Database
├── server_payload.zip                  # نسخة مضغوطة من حزمة السيرفر كنسخة احتياطية
└── win-unpacked/                       # النسخة المحمولة القابلة للتشغيل المباشر للتجربة السريعة
```

> [!IMPORTANT]
> برنامج التثبيت `منظومة السحابة Setup 1.0.0.exe` مبرمج داخلياً عبر NSIS ليبحث في نفس المجلد الموجود به (`$EXEDIR`) عن مجلد `server_payload` أو ملف `server_payload.zip` ليقوم بنشر وتثبيت Apache و PHP على جهاز العميل.

## 2. قاعدة مجلد `runtime/` وأرشيف `runtime.7z` وعلاقتهما بـ Git

* **لماذا لا يوجد مجلد `runtime/` على مستودع GitHub؟**  
  مجلد `runtime/` يحتوي على ملفات ثنائية ضخمة (Apache 2.4 كامل + PHP 8.4 مجمع + أدوات SSL) بحجم مئات الميجابايت، لذلك تم استثناؤه في ملف `.gitignore` للحفاظ على سرعة المستودع وخفة حجمه.
* **البديل المرفوع على Git:**  
  يوجد أرشيف مضغوط رسمي في جذر المشروع اسمه: **`runtime.7z`**.
* **الخطوة الصفرية الإلزامية قبل البناء:**  
  قبل تنفيذ أمر البناء الشامل، يجب التأكد من فك ضغط الأرشيف ليصبح مجلد `runtime/` متوفراً:
  ```bash
  npm run setup:runtime
  ```
  *(أو يدوياً عبر: `tar -xf runtime.7z -C .`)*.  
  *(ملاحظة: سكريبت البناء `scripts/pack-server-payload.js` يقوم تلقائياً بفك ضغطه إذا لم يجده، ولكن يفضل تشغيله مسبقاً للتأكد).*

## 3. خطوات البناء من الصفر وأمر `npm run build:all`

عندما ترغب في إعادة بناء المنظومة بالكامل من الصفر (حتى لو قمت بحذف مجلد `dist/` تماماً)، يتم ذلك بأمر واحد فقط:

```bash
npm run build:all
```

### ماذا يفعل هذا الأمر تلقائياً بالترتيب؟
1. **`npm run build` (Vite Build):**  
   يقوم بتجميع أصول الواجهة الرسومية (React 19 + TypeScript + Tailwind CSS) وضغطها وإنتاج ملفات `public/build`.
2. **`node scripts/pack-server-payload.js`:**  
   * يتأكد من وجود مجلد `runtime/` (أو يفكه من `runtime.7z`).
   * ينسخ مفسر PHP 8.4 المحمول إلى `dist/server_payload/php`.
   * ينسخ خادم Apache 2.4 ومحرك mkcert إلى `dist/server_payload/apache`.
   * ينسخ ملفات Laravel الأساسية ومجلد `vendor` بالكامل إلى `dist/server_payload/server`.
   * ينشئ الأرشيف المضغوط الاحتياطي `dist/server_payload.zip`.
3. **`npx electron-builder --win nsis`:**  
   * يقوم بتجميع تطبيق سطح المكتب (Electron 33).
   * يدمج سكريبت التثبيت `electron/installer.nsh`.
   * يولد ملف التثبيت المكتبي النهائي: `dist/منظومة السحابة Setup 1.0.0.exe`.

## 4. القاعدة الذهبية لنقل وتثبيت المنظومة عند العميل

> [!CAUTION]
> **تحذير حاسم ومؤكد:** لا تنقل ملف `منظومة السحابة Setup 1.0.0.exe` بمفرده معزولاً إلى فلاشة USB أو جهاز العميل!

### الطريقة الصحيحة للنقل:
* انقل **مجلد `dist` بالكامل**، أو على الأقل ضع في نفس المجلد:
  1. ملف `منظومة السحابة Setup 1.0.0.exe`
  2. مجلد `server_payload/` (أو ملف `server_payload.zip`)

### ماذا يفعل برنامج التثبيت تلقائياً عند تشغيله على جهاز العميل؟
عند تشغيل ملف التثبيت على جهاز جديد كمسؤول (`Run as Administrator`):
1. ينسخ ملفات PHP إلى `C:\php-8.4.24`.
2. ينسخ خادم Apache إلى `C:\Apache24`.
3. يسجل خدمة `Apache2.4` كخدمة نظام تلقائية في ويندوز (`sc config Apache2.4 start= auto`).
4. يبدأ تشغيل خادم Apache فوراً (`net start Apache2.4`).
5. يثبت شهادة الـ Root CA المحلية عبر `mkcert -install` لتفعيل الـ HTTPS الصامت بدون تحذيرات.
6. يضيف مسارات `C:\php-8.4.24` و `C:\Apache24\bin` إلى متغير بيئة النظام العام (**System PATH**).
7. ينشئ اختصار **«إعدادات خادم السحابة»** على سطح المكتب.

## 5. المتطلبات الإلزامية المسبقة على جهاز العميل الجديد

جهاز العميل الجديد (الذي لا يحتوي على أي برامج مسبقة) يحتاج فقط إلى شيئين بسيطين:

1. **تثبيت خادم MySQL:**  
   * المنظومة تحتاج لقاعدة بيانات MySQL لتخزين البيانات.
   * يتم تثبيت **MySQL Community Server** أو **MySQL Workbench** على جهاز العميل (أو ربطه بسيرفر خارجي إن وُجد).
2. **حزمة Visual C++ Redistributable (`vc_redist.x64.exe`):**  
   * كلا الخادمين (Apache و PHP) على نظام Windows مبنيان باستخدام Visual Studio C++، ويتطلبان مكتبة `Visual C++ 2015-2022 x64`.
   * *(غالباً ما يقوم مثبت MySQL بتثبيتها تلقائياً، ولكن احتفظ بالملف لتثبيته في ثوانٍ عند الحاجة لتفادي خطأ `VCRUNTIME140.dll missing`)*.
3. **التشغيل بصلاحية المسؤول (Run as Administrator):**  
   * يجب النقر بيمين الفأرة على ملف الـ Setup واختيار **تشغيل كمسؤول** ليتمكن من إنشاء المجلدات في `C:\` وتسجيل خدمات ويندوز.

## 6. نظام الاسترداد التلقائي وخادم Apache المدمج

إذا قام العميل أو مستخدم الكاشير بإيقاف خادم Apache يدوياً، أو إذا أعاد تشغيل الجهاز ولم تعمل الخدمة:

1. **منع الشاشة السوداء:**  
   لن تظهر أي شاشة سوداء أو أخطاء متصفح جافة؛ يلتقط التطبيق انقطاع الاتصال خلال **300 ملي ثانية**.
2. **شاشة الاسترداد الفورية (`server-offline.html`):**  
   تظهر فوراً شاشة أنيقة بتصميم المنظومة تحتوي على:
   * **زر «تشغيل خادم Apache الآن»:** يقوم بطلب ترقية صلاحيات المسؤول (UAC Elevation عبر PowerShell RunAs) وتشغيل الخدمة تلقائياً في ثوانٍ.
   * **زر «إعادة محاولة الاتصال»:** لفحص المنافذ وإعادة التحميل.
   * **زر «فتح أداة إعدادات الخادم»:** لتعديل ضبط السيرفر أو فحص الاتصال.
3. **التحويل التلقائي:**  
   بمجرد استجابة الخادم على المنفذ `80` أو `443`، يتحول الزر للأخضر وتنقله المنظومة فوراً إلى شاشة المبيعات `/invoices/create`.

## 7. بطاقة الأوامر السريعة للمطور (Cheat Sheet)

عند العودة للمشروع بعد أشهر طويلة، هذه هي الخطوات السريعة بالترتيب:

```bash
# 1. سحب آخر التحديثات
git pull

# 2. فك ضغط بيئة التشغيل المحمولة (إذا لم يكن مجلد runtime مفكوكاً)
npm run setup:runtime

# 3. بناء المنظومة بالكامل وإنتاج حزمة التثبيت
npm run build:all

# 4. النشر:
# انسخ مجلد dist/ بالكامل إلى فلاشة USB وثبت على جهاز العميل بتشغيل:
# "منظومة السحابة Setup 1.0.0.exe" كمسؤول (Run as Administrator)
```
