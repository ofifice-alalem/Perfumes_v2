================================================================================
                    المرحلة 6: عمليات الموردين
================================================================================

📋 نظرة عامة:
--------------
هذه المرحلة تغطي كل ما يتعلق بالموردين من شراء وإدارة مخزون ومدفوعات وتسويات ومرتجعات.
المورد هو مصدر المخزون — كل كمية موجودة في النظام جاءت من فاتورة شراء.

التدفق الأساسي:
   مورد → فاتورة شراء → أسطر شراء → stock يزيد → دفع للمورد
   مورد → مرتجع → أسطر مرتجع → stock ينقص → تسوية (تلقائية أو يدوية)

================================================================================
                    🗂️ الجداول المستخدمة في هذه المرحلة
================================================================================

   1. suppliers              → بيانات الموردين (تم تعريفهم في step_4)
   2. purchases              → رأس فاتورة الشراء
   3. purchase_items         → أسطر الشراء (منتج + كمية + سعر)
   4. supplier_payments      → المدفوعات للموردين
   5. supplier_settlements   → التسويات مع الموردين
   6. purchase_returns       → رأس سجل المرتجع
   7. purchase_return_items  → أسطر المرتجع (منتج + كمية + سعر)


================================================================================
                        1️⃣  purchases
================================================================================

📌 الوظيفة:
   رأس فاتورة الشراء — نفس منطق invoices لكن معكوس.
   كل عملية شراء من مورد = فاتورة شراء.
   الإجمالي يُحسب من مجموع أسطر purchase_items.

📌 الحقول المهمة:
   supplier_id    → المورد
   total          → الإجمالي (cached من purchase_items)
   paid_amount    → المدفوع (cached من supplier_payments)
   due_amount     → المتبقي = total - paid_amount
   payment_status → حالة الدفع (unpaid / partial / paid)
   notes          → ملاحظات

📌 قواعد الحساب:
   total          = SUM(purchase_items.line_total)
   paid_amount    = SUM(supplier_payments.amount WHERE purchase_id = this.id)
   due_amount     = total - paid_amount
   payment_status:
     paid_amount = 0         → 'unpaid'
     0 < paid_amount < total → 'partial'
     paid_amount >= total    → 'paid'


================================================================================
                        2️⃣  purchase_items
================================================================================

📌 الوظيفة:
   سطر واحد لكل منتج داخل فاتورة الشراء.
   عند إضافة السطر: products.stock += quantity تلقائياً.
   يحفظ سعر الشراء وقت الشراء (snapshot) لتتبع تغير الأسعار.

📌 الحقول المهمة:
   purchase_id → فاتورة الشراء
   product_id  → المنتج
   quantity    → الكمية المشتراة
   unit_cost   → سعر الوحدة وقت الشراء (snapshot)
   line_total  → الإجمالي = unit_cost × quantity

📌 قاعدة تحديث المخزون:
   إضافة سطر:  products.stock += quantity
   حذف سطر:    products.stock -= quantity
   تعديل سطر:  products.stock += (new_quantity - old_quantity)

📌 ملاحظة — إدخال السعر:
   البائع يدخل الكمية والسعر الإجمالي للسطر.
   النظام يحسب unit_cost = line_total / quantity تلقائياً.


================================================================================
                        3️⃣  supplier_payments
================================================================================

📌 الوظيفة:
   كل دفعة تدفعها للمورد.
   مرتبطة بالمورد مباشرة (supplier_id إجباري).
   مرتبطة بفاتورة الشراء اختيارياً (purchase_id nullable).

📌 الحقول المهمة:
   supplier_id       → المورد (إجباري)
   purchase_id       → فاتورة الشراء (nullable — للمرجعية فقط)
   payment_method_id → وسيلة الدفع
   amount            → المبلغ المدفوع
   notes             → ملاحظة

📌 قواعد:
   purchase_id = NULL  → دفعة مستقلة لسداد الدين العام للمورد
   purchase_id موجود  → دفعة مرتبطة بفاتورة شراء محددة
   عند حذف فاتورة شراء: purchase_id يصبح NULL (nullOnDelete)


================================================================================
                        4️⃣  supplier_settlements
================================================================================

📌 الوظيفة:
   التسويات مع الموردين — المورد يُعيد مبلغاً للمتجر.
   تُستخدم عندما يكون total_debt سالباً (المورد دائن للمتجر).
   أسباب: رد بضاعة، خصم، إلغاء فاتورة مدفوعة، ...

📌 الحقول المهمة:
   supplier_id       → المورد (إجباري)
   purchase_id       → فاتورة الشراء المرجعية (nullable)
   payment_method_id → وسيلة رد المبلغ
   amount            → المبلغ المُرجَع
   notes             → سبب التسوية

📌 قاعدة:
   التسوية تزيد total_debt للمورد (المورد دائن للمتجر)
   إذا كان total_debt سالباً → المورد دائن للمتجر (يظهر بلون مختلف)


================================================================================
                        5️⃣  purchase_returns
================================================================================

📌 الوظيفة:
   رأس سجل المرتجع — إرجاع بضاعة للمورد.
   كل عملية إرجاع تخصم من المخزون وقد تُنشئ تسوية مالية.

📌 الحقول المهمة:
   supplier_id   → المورد (إجباري)
   purchase_id   → فاتورة الشراء المرجعية (nullable)
   settlement_id → التسوية المرتبطة (nullable — تُنشأ تلقائياً أو يدوياً)
   total         → إجمالي قيمة المرتجع
   notes         → ملاحظات

📌 قواعد:
```
- purchase_id = NULL  → مرتجع مستقل غير مرتبط بفاتورة محددة
- purchase_id موجود  → مرتجع من فاتورة شراء محددة
- settlement_id = NULL  → لم تُنشأ تسوية بعد أو لا حاجة لها
- settlement_id موجود  → تسوية مرتبطة بهذا المرتجع
```


================================================================================
                        6️⃣  purchase_return_items
================================================================================

📌 الوظيفة:
   أسطر المرتجع — كل سطر يمثل منتجاً واحداً مع كميته وسعره.
   عند إضافة السطر: products.stock -= quantity فوراً.

📌 الحقول المهمة:
   purchase_return_id → سجل المرتجع
   product_id         → المنتج
   quantity           → الكمية المرتجعة
   unit_cost          → سعر الوحدة وقت الإرجاع (snapshot)
   line_total         → الإجمالي = unit_cost × quantity

📌 قاعدة تحديث المخزون:
   إضافة سطر:  products.stock -= quantity
   حذف سطر:    products.stock += quantity
   حذف السجل:  يُعاد مخزون كل الأسطر قبل الحذف (CASCADE)


================================================================================
                    🔄 تدفق العمل الكامل
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 1: شراء من مورد مسجّل                                                │
└─────────────────────────────────────────────────────────────────────────────┘

   اختيار المورد
         ↓
   إنشاء فاتورة شراء
         ↓
   إضافة المنتجات (كل سطر → stock يزيد فوراً)
         ↓
   تسجيل دفع (كامل أو جزئي)
         ↓
   ✅ الفاتورة مكتملة — المخزون محدث


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 2: شراء من مورد نقدي                                                 │
└─────────────────────────────────────────────────────────────────────────────┘

   اختيار "مورد نقدي" (id=1)
         ↓
   إضافة المنتجات
         ↓
   يجب الدفع الكامل قبل التأكيد (إجباري)
         ↓
   ✅ الفاتورة مكتملة


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 3: سداد دين مستقل                                                    │
└─────────────────────────────────────────────────────────────────────────────┘

   من /supplier-payments أو من صفحة المورد أو من صفحة فاتورة الشراء
         ↓
   اختيار المورد + المبلغ + وسيلة الدفع
         ↓
   POST /supplier-payments { supplier_id, payment_method_id, amount }
         ↓
   suppliers.total_debt يُعاد حسابه تلقائياً


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 4: تسوية (المورد دائن)                                               │
└─────────────────────────────────────────────────────────────────────────────┘

   total_debt < 0 (المورد دائن للمتجر)
         ↓
   من /supplier-settlements أو من صفحة المورد أو فاتورة الشراء
         ↓
   اختيار المورد + المبلغ + وسيلة الرد
         ↓
   POST /supplier-settlements { supplier_id, payment_method_id, amount }
         ↓
   suppliers.total_debt يُعاد حسابه تلقائياً


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 5: مرتجع — مورد نقدي                                                 │
└─────────────────────────────────────────────────────────────────────────────┘

   إنشاء سجل مرتجع + إضافة المنتجات
         ↓
   stock -= quantity لكل سطر
         ↓
   تسوية تلقائية بقيمة المرتجع (دائماً)
         ↓
   total_debt للمورد يُعاد حسابه


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 6: مرتجع — مورد مسجّل                                                │
└─────────────────────────────────────────────────────────────────────────────┘

   إنشاء سجل مرتجع + إضافة المنتجات
         ↓
   stock -= quantity لكل سطر
         ↓
   النظام يحسب total_debt بعد الإرجاع
         ↓
   ┌─────────────────────────────────────────────────────┐
   │ total_debt بعد الإرجاع > 0                          │
   │   → لا تسوية — المرتجع يُخفّض الدين فقط            │
   ├─────────────────────────────────────────────────────┤
   │ total_debt بعد الإرجاع <= 0                         │
   │   → يظهر خيار: [إنشاء تسوية] [لاحقاً]              │
   └─────────────────────────────────────────────────────┘

================================================================================
                    ⚙️ قواعد التحديث التلقائي (Observers)
================================================================================

كل تغيير في الجداول أدناه يُطلق Observer يحدّث الحقول المؤقتة تلقائياً.

┌─────────────────────────────────────────────────────────────────────────────┐
│ PurchaseItemObserver                                                        │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted / updated في purchase_items
يحدّث:
   purchases.total          = SUM(purchase_items.line_total)
   purchases.due_amount     = total - paid_amount
   purchases.payment_status = حسب القاعدة
   suppliers.total_purchases = SUM(purchases.total)
   suppliers.total_debt      = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ SupplierPaymentObserver                                                     │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted في supplier_payments
يحدّث:
   إذا purchase_id موجود:
      purchases.paid_amount    = SUM(supplier_payments.amount WHERE purchase_id)
      purchases.due_amount     = total - paid_amount
      purchases.payment_status = حسب القاعدة
   دائماً:
      suppliers.total_paid = SUM(supplier_payments.amount)
      suppliers.total_debt = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ SupplierSettlementObserver                                                  │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted في supplier_settlements
يحدّث:
   suppliers.total_settlements = SUM(supplier_settlements.amount)
   suppliers.total_debt        = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ PurchaseReturnItemObserver                                                  │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted في purchase_return_items
يحدّث:
   purchase_returns.total      = SUM(purchase_return_items.line_total)
   suppliers.total_returns     = SUM(purchase_returns.total)
   suppliers.total_debt        = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ معادلة total_debt للمورد                                              │
└─────────────────────────────────────────────────────────────────────────────┘

total_debt = total_purchases - total_paid + total_settlements - total_returns

قاعدة: supplier_id = 1 (مورد نقدي) → لا يُحدَّث أي حقل مالي

────────────────────────────────────────────────────────────────────────────────
1. Soft Deletes
────────────────────────────────────────────────────────────────────────────────
الجداول التي تحتوي على deleted_at:
   - purchases
   - purchase_returns
   - supplier_payments
   - supplier_settlements

النماذج تستخدم SoftDeletes trait.
السجلات المحذوفة لا تُحذف فعلياً من قاعدة البيانات بل تُخفى.


────────────────────────────────────────────────────────────────────────────────
2. Restore (استعادة السجلات المحذوفة)
────────────────────────────────────────────────────────────────────────────────
PurchaseController::restore
   - تستعيد الفاتورة المحذوفة
   - تستعيد المدفوعات والتسويات المرتبطة بها
   - تُعيد إضافة المخزون لجميع أسطرها
   - تُعيد حساب أرقام المورد

PurchaseReturnController::restore
   - تستعيد المرتجع المحذوف
   - تستعيد التسويات المرتبطة به
   - تُعيد خصم المخزون لجميع أسطره
   - تُعيد حساب أرقام المورد

Route:
   POST /purchases/{id}/restore
   POST /purchase-returns/{id}/restore


────────────────────────────────────────────────────────────────────────────────
3. حقول Recovery Tracking في purchase_returns
────────────────────────────────────────────────────────────────────────────────
أعمدة إضافية في جدول purchase_returns:
   recovered_amount  → إجمالي ما استُرد من تسويات مرتبطة بهذا المرتجع
   due_recovery      → المتبقي = total - recovered_amount
   recovery_status   → حالة الاسترداد (unpaid / partial / paid)

يُحدَّث تلقائياً عبر SupplierSettlementObserver عند إنشاء/حذف تسوية مرتبطة.


────────────────────────────────────────────────────────────────────────────────
4. عمود purchase_return_id في supplier_settlements
────────────────────────────────────────────────────────────────────────────────
عمود إضافي في جدول supplier_settlements:
   purchase_return_id → ربط مباشر بالمرتجع الذي أنشأ هذه التسوية (nullable)

يتيح تتبع أي تسوية نشأت من أي مرتجع.
عند حذف المرتجع: purchase_return_id يصبح NULL (nullOnDelete).

5. نظام Auditing
────────────────────────────────────────────────────────────────────────────────
الحزمة: owen-it/laravel-auditing
جميع النماذج تُطبّق Auditable:
   Purchase, PurchaseItem, SupplierPayment, SupplierSettlement,
   PurchaseReturn, PurchaseReturnItem

جدول audits يسجل كل عملية create/update/delete مع:
   - المستخدم الذي نفّذها
   - القيم القديمة والجديدة
   - التوقيت


────────────────────────────────────────────────────────────────────────────────
6. حماية المورد النقدي في Supplier Model
────────────────────────────────────────────────────────────────────────────────
في boot():
   - يمنع تعديل المورد ذو id=1 → abort(403)
   - يمنع حذف المورد ذو id=1  → abort(403)

Helper methods:
   scopeWithoutCash()  → يستثني المورد النقدي من أي query
   isCashSupplier()    → يتحقق إذا كان المورد هو المورد النقدي


────────────────────────────────────────────────────────────────────────────────
7. خيار delete_payments و delete_settlements عند حذف فاتورة
────────────────────────────────────────────────────────────────────────────────
PurchaseController::destroy يقبل:
   delete_payments    (boolean) → إذا true: يحذف المدفوعات المرتبطة
                                  إذا false: يفصلها فقط (purchase_id → NULL)
   delete_settlements (boolean) → نفس المنطق للتسويات

السلوك الافتراضي (false): المدفوعات والتسويات تبقى كسجل مالي للمورد.


────────────────────────────────────────────────────────────────────────────────
8. فلترة المنتجات حسب المورد في صفحة إنشاء المرتجع
────────────────────────────────────────────────────────────────────────────────
PurchaseReturnController::create:
   - مورد نقدي (id=1)  → يُرجع جميع المنتجات
   - مورد مسجّل       → يُرجع فقط المنتجات التي اشتراها هذا المورد
                         (عبر purchase_items → purchases → supplier_id)


────────────────────────────────────────────────────────────────────────────────
9. حساب Live لبيانات المورد النقدي
────────────────────────────────────────────────────────────────────────────────
في SupplierRepository::allOrdered():
   المورد النقدي (id=1) لا تُحدَّث حقوله المالية عبر Observers.
   عند عرض القائمة يُحسب مباشرةً من الجداول:
      total_purchases = SUM(purchases.total WHERE supplier_id=1)
      total_paid      = SUM(supplier_payments.amount WHERE supplier_id=1)
      total_returns   = SUM(purchase_returns.total WHERE supplier_id=1)
