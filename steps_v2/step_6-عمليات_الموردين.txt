================================================================================
                    المرحلة 6: عمليات الموردين
================================================================================

📋 نظرة عامة:
--------------
هذه المرحلة تغطي كل ما يتعلق بالموردين من شراء وإدارة مخزون ومدفوعات وتسويات.
المورد هو مصدر المخزون — كل كمية موجودة في النظام جاءت من فاتورة شراء.

التدفق الأساسي:
   مورد → فاتورة شراء → أسطر شراء → stock يزيد → دفع للمورد

================================================================================
                    🗂️ الجداول المستخدمة في هذه المرحلة
================================================================================

   1. suppliers              → بيانات الموردين (تم تعريفهم في step_4)
   2. purchases              → رأس فاتورة الشراء
   3. purchase_items         → أسطر الشراء (منتج + كمية + سعر)
   4. supplier_payments      → المدفوعات للموردين
   5. supplier_settlements   → التسويات مع الموردين


================================================================================
                        1️⃣  purchases
================================================================================

📌 الوظيفة:
   رأس فاتورة الشراء — نفس منطق invoices لكن معكوس.
   كل عملية شراء من مورد = فاتورة شراء.
   الإجمالي يُحسب من مجموع أسطر purchase_items.

📌 الحقول المهمة:
   supplier_id    → المورد
   total          → الإجمالي (cached من purchase_items)
   paid_amount    → المدفوع (cached من supplier_payments)
   due_amount     → المتبقي = total - paid_amount
   payment_status → حالة الدفع (unpaid / partial / paid)
   notes          → ملاحظات

📌 قواعد الحساب:
   total          = SUM(purchase_items.line_total)
   paid_amount    = SUM(supplier_payments.amount WHERE purchase_id = this.id)
   due_amount     = total - paid_amount
   payment_status:
     paid_amount = 0         → 'unpaid'
     0 < paid_amount < total → 'partial'
     paid_amount >= total    → 'paid'


================================================================================
                        2️⃣  purchase_items
================================================================================

📌 الوظيفة:
   سطر واحد لكل منتج داخل فاتورة الشراء.
   عند إضافة السطر: products.stock += quantity تلقائياً.
   يحفظ سعر الشراء وقت الشراء (snapshot) لتتبع تغير الأسعار.

📌 الحقول المهمة:
   purchase_id → فاتورة الشراء
   product_id  → المنتج
   quantity    → الكمية المشتراة
   unit_cost   → سعر الوحدة وقت الشراء (snapshot)
   line_total  → الإجمالي = unit_cost × quantity

📌 قاعدة تحديث المخزون:
   إضافة سطر:  products.stock += quantity
   حذف سطر:    products.stock -= quantity
   تعديل سطر:  products.stock += (new_quantity - old_quantity)

📌 ملاحظة — إدخال السعر:
   البائع يدخل الكمية والسعر الإجمالي للسطر.
   النظام يحسب unit_cost = line_total / quantity تلقائياً.


================================================================================
                        3️⃣  supplier_payments
================================================================================

📌 الوظيفة:
   كل دفعة تدفعها للمورد.
   مرتبطة بالمورد مباشرة (supplier_id إجباري).
   مرتبطة بفاتورة الشراء اختيارياً (purchase_id nullable).

📌 الحقول المهمة:
   supplier_id       → المورد (إجباري)
   purchase_id       → فاتورة الشراء (nullable — للمرجعية فقط)
   payment_method_id → وسيلة الدفع
   amount            → المبلغ المدفوع
   notes             → ملاحظة

📌 قواعد:
   purchase_id = NULL  → دفعة مستقلة لسداد الدين العام للمورد
   purchase_id موجود  → دفعة مرتبطة بفاتورة شراء محددة
   عند حذف فاتورة شراء: purchase_id يصبح NULL (nullOnDelete)


================================================================================
                        4️⃣  supplier_settlements
================================================================================

📌 الوظيفة:
   التسويات مع الموردين — المورد يُعيد مبلغاً للمتجر.
   تُستخدم عندما يكون total_debt سالباً (المورد دائن للمتجر).
   أسباب: رد بضاعة، خصم، إلغاء فاتورة مدفوعة، ...

📌 الحقول المهمة:
   supplier_id       → المورد (إجباري)
   purchase_id       → فاتورة الشراء المرجعية (nullable)
   payment_method_id → وسيلة رد المبلغ
   amount            → المبلغ المُرجَع
   notes             → سبب التسوية

📌 قاعدة:
   التسوية تزيد total_debt للمورد (المورد دائن للمتجر)
   إذا كان total_debt سالباً → المورد دائن للمتجر (يظهر بلون مختلف)


================================================================================
                    🔄 تدفق العمل الكامل
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 1: شراء من مورد مسجّل                                                │
└─────────────────────────────────────────────────────────────────────────────┘

   اختيار المورد
         ↓
   إنشاء فاتورة شراء
         ↓
   إضافة المنتجات (كل سطر → stock يزيد فوراً)
         ↓
   تسجيل دفع (كامل أو جزئي)
         ↓
   ✅ الفاتورة مكتملة — المخزون محدث


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 2: شراء من مورد نقدي                                                 │
└─────────────────────────────────────────────────────────────────────────────┘

   اختيار "مورد نقدي" (id=1)
         ↓
   إضافة المنتجات
         ↓
   يجب الدفع الكامل قبل التأكيد (إجباري)
         ↓
   ✅ الفاتورة مكتملة


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 3: سداد دين مستقل                                                    │
└─────────────────────────────────────────────────────────────────────────────┘

   من /supplier-payments أو من صفحة المورد أو من صفحة فاتورة الشراء
         ↓
   اختيار المورد + المبلغ + وسيلة الدفع
         ↓
   POST /supplier-payments { supplier_id, payment_method_id, amount }
         ↓
   suppliers.total_debt يُعاد حسابه تلقائياً


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 4: تسوية (المورد دائن)                                               │
└─────────────────────────────────────────────────────────────────────────────┘

   total_debt < 0 (المورد دائن للمتجر)
         ↓
   من /supplier-settlements أو من صفحة المورد أو فاتورة الشراء
         ↓
   اختيار المورد + المبلغ + وسيلة الرد
         ↓
   POST /supplier-settlements { supplier_id, payment_method_id, amount }
         ↓
   suppliers.total_debt يُعاد حسابه تلقائياً


================================================================================
                    🖥️ الصفحات
================================================================================

   /suppliers                  → قائمة الموردين + CRUD + دفعة/تسوية مباشرة
   /purchases                  → قائمة فواتير الشراء مع فلتر
   /purchases/create           → POS style لإنشاء فاتورة شراء
   /purchases/{id}             → تفاصيل فاتورة + أسطر + وضع مالي للمورد
   /supplier-payments          → قائمة المدفوعات + إنشاء دفعة مستقلة
   /supplier-payments/{id}     → تفاصيل دفعة + بيانات المورد + فاتورة مرتبطة
   /supplier-settlements       → قائمة التسويات + إنشاء تسوية مستقلة
   /supplier-settlements/{id}  → تفاصيل تسوية + بيانات المورد + فاتورة مرتبطة


================================================================================
                        ⚠️ قواعد العمل المهمة
================================================================================

📌 المخزون:
1.  ✅ products.stock += quantity عند إضافة كل سطر شراء
2.  ✅ products.stock -= quantity عند حذف سطر شراء
3.  ✅ products.stock += (new_qty - old_qty) عند تعديل سطر شراء
4.  ✅ حذف فاتورة شراء → يُعاد خصم مخزون جميع أسطرها
5.  ✅ unit_cost يُسجَّل وقت الشراء ولا يتغير (snapshot)

📌 الدفع:
6.  ✅ مورد نقدي (id=1) → يجب الدفع الكامل فوراً
7.  ✅ مورد مسجّل → يمكن الدفع الجزئي أو المؤجل
8.  ✅ الدفعة تُخفّض total_debt للمورد
9.  ✅ لا يمكن أن يتجاوز paid_amount قيمة total في فاتورة واحدة

📌 التسويات:
10. ✅ التسوية تُستخدم فقط عندما يكون total_debt < 0 (المورد دائن)
11. ✅ التسوية تزيد total_debt (تُقلّص الدائنية)
12. ✅ لا يمكن إنشاء تسوية إذا كان total_debt > 0 (استخدم الدفعة)

📌 الحذف:
13. ✅ حذف فاتورة شراء → purchase_id في supplier_payments يصبح NULL
14. ✅ حذف فاتورة شراء → المدفوعات تبقى كسجل مالي للمورد
15. ✅ حذف purchase → يحذف purchase_items تلقائياً (CASCADE)
