================================================================================
                    المرحلة 7: عمليات العملاء
================================================================================

📋 نظرة عامة:
--------------
هذه المرحلة تغطي كل ما يتعلق بالعملاء من بيع وفواتير ومدفوعات وتسويات ومرتجعات.
التدفق الأساسي:
   عميل → فاتورة بيع → أسطر بيع → stock ينقص → دفع من العميل
   عميل → مرتجع → أسطر مرتجع → stock يزيد → تسوية (تلقائية أو يدوية)

================================================================================
                    🗂️ الجداول المستخدمة في هذه المرحلة
================================================================================

   1. customers             → بيانات العملاء (تم تعريفهم في step_4)
   2. invoices              → رأس فاتورة البيع
   3. invoice_items         → أسطر البيع (منتج + كمية + سعر)
   4. payments              → المدفوعات من العملاء
   5. settlements           → التسويات مع العملاء
   6. invoice_returns       → رأس سجل المرتجع من العميل
   7. invoice_return_items  → أسطر المرتجع (منتج + كمية + سعر)


================================================================================
                        1️⃣  invoices
================================================================================

📌 الوظيفة:
   رأس فاتورة البيع — تجمع معلومات البائع والعميل وحالة الدفع.
   الإجمالي يُحسب من مجموع أسطر invoice_items.

📌 الحقول المهمة:
   user_id        → البائع
   customer_id    → العميل (NULL = زبون نقدي)
   customer_type  → نوع العميل (regular / vip) — مرجع فقط
   total          → الإجمالي (cached من invoice_items)
   paid_amount    → المدفوع (cached من payments)
   due_amount     → المتبقي = total - paid_amount
   payment_status → حالة الدفع (unpaid / partial / paid)
   notes          → ملاحظات

📌 قواعد الحساب:
   total          = SUM(invoice_items.line_total)
   paid_amount    = SUM(payments.amount WHERE invoice_id = this.id)
   due_amount     = total - paid_amount
   payment_status:
     paid_amount = 0         → 'unpaid'
     0 < paid_amount < total → 'partial'
     paid_amount >= total    → 'paid'


================================================================================
                        2️⃣  invoice_items
================================================================================

📌 الوظيفة:
   سطر واحد لكل منتج داخل الفاتورة.
   يحفظ السعر وقت البيع (snapshot) — لا يتأثر بأي تغيير لاحق في الأسعار.
   عند إضافة السطر: products.stock -= quantity فوراً.

📌 الحقول المهمة:
   invoice_id  → الفاتورة
   product_id  → المنتج
   size_id     → الحجم (nullable)
   sale_type   → نوع البيع
   quantity    → الكمية
   unit_price  → سعر الوحدة وقت البيع (snapshot) — يدخله البائع ضمن المدى
   line_total  → الإجمالي = unit_price × quantity

📌 ENUM sale_type:
   'tier_decant'  → عطر زيتي بالحجم       | size_id مطلوب | stock -= size.value
   'unit_decant'  → عطر أصلي بالتقسيم     | size_id مطلوب | stock -= size.value
   'full_bottle'  → عطر أصلي عبوة كاملة   | size_id = NULL | stock -= bottle_volume
   'unit_based'   → بخور / وشق / مبخرة    | size_id = NULL | stock -= quantity

📌 منطق السعر:
   كل منتج له سعران: price_regular (الأعلى) و price_vip (الأدنى)
   البائع يدخل unit_price يدوياً ضمن المدى:
      price_vip <= unit_price <= price_regular
   customer_type في الفاتورة مرجع فقط — لا يُحدد السعر تلقائياً


================================================================================
                        3️⃣  payments
================================================================================

📌 الوظيفة:
   كل دفعة مرتبطة بالعميل مباشرة (customer_id إجباري).
   مرتبطة بالفاتورة اختيارياً (invoice_id nullable).
   يسمح بسداد الدين بشكل مستقل عن أي فاتورة.

📌 الحقول المهمة:
   customer_id       → العميل (إجباري)
   invoice_id        → الفاتورة (nullable — للمرجعية فقط)
   payment_method_id → وسيلة الدفع
   amount            → المبلغ المدفوع
   notes             → ملاحظة

📌 قواعد:
   invoice_id = NULL  → دفعة مستقلة لسداد الدين العام للعميل
   invoice_id موجود  → دفعة مرتبطة بفاتورة محددة
   عند حذف فاتورة: invoice_id يصبح NULL — الدفعة تبقى كسجل مالي


================================================================================
                        4️⃣  settlements
================================================================================

📌 الوظيفة:
   التسويات — المتجر يُعيد مبلغاً للعميل.
   تُستخدم عندما يكون total_debt سالباً (المتجر مدين للعميل).
   أسباب: مرتجع بضاعة، إلغاء فاتورة مدفوعة، خصم، ...

📌 الحقول المهمة:
   customer_id       → العميل (إجباري)
   invoice_id        → الفاتورة المرجعية (nullable)
   payment_method_id → وسيلة رد المبلغ
   amount            → المبلغ المُرجَع
   notes             → سبب التسوية

📌 قاعدة:
   التسوية تزيد total_debt للعميل (المتجر مدين للعميل)
   إذا كان total_debt سالباً → المتجر مدين للعميل (يظهر بلون مختلف)


================================================================================
                        5️⃣  invoice_returns
================================================================================

📌 الوظيفة:
   رأس سجل المرتجع من العميل.
   كل عملية إرجاع تزيد المخزون وقد تُنشئ تسوية مالية.

📌 الحقول المهمة:
   customer_id   → العميل (إجباري)
   invoice_id    → الفاتورة المرجعية (nullable)
   settlement_id → التسوية المرتبطة (nullable — تُنشأ تلقائياً أو يدوياً)
   total         → إجمالي قيمة المرتجع
   notes         → ملاحظات

📌 منطق التسوية عند الإرجاع:
   زبون نقدي (id=1):
     → تسوية تلقائية دائماً بقيمة المرتجع

   زبون مسجّل:
     → النظام يحسب total_debt بعد الإرجاع
     → إذا total_debt بعد الإرجاع > 0:
          لا تسوية — المرتجع يُخفّض الدين فقط
     → إذا total_debt بعد الإرجاع <= 0:
          يظهر خيار: [إنشاء تسوية] [لاحقاً]


================================================================================
                        6️⃣  invoice_return_items
================================================================================

📌 الوظيفة:
   أسطر المرتجع من العميل — كل سطر يمثل منتجاً واحداً.
   عند إضافة السطر: products.stock += quantity فوراً.

📌 الحقول المهمة:
   invoice_return_id → سجل المرتجع
   product_id        → المنتج
   quantity          → الكمية المرتجعة
   unit_price        → سعر الوحدة وقت الإرجاع (snapshot)
   line_total        → الإجمالي = unit_price × quantity

📌 قاعدة تحديث المخزون:
   إضافة سطر:  products.stock += quantity
   حذف سطر:    products.stock -= quantity
   حذف السجل:  يُعاد خصم مخزون كل الأسطر قبل الحذف (CASCADE)


================================================================================
                    🔄 تدفق العمل الكامل
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 1: بيع لزبون نقدي                                                    │
└─────────────────────────────────────────────────────────────────────────────┘

   اختيار "زبون نقدي" (id=1)
         ↓
   إضافة المنتجات (كل سطر → stock ينقص فوراً)
         ↓
   يجب الدفع الكامل قبل التأكيد (إجباري)
         ↓
   ✅ الفاتورة مكتملة


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 2: بيع لزبون مسجّل                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

   اختيار العميل → يظهر دينه السابق
         ↓
   إضافة المنتجات
         ↓
   تسجيل دفع (كامل أو جزئي أو بدون دفع)
         ↓
   ✅ الفاتورة مكتملة — الدين يُحدَّث تلقائياً


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 3: سداد دين مستقل                                                    │
└─────────────────────────────────────────────────────────────────────────────┘

   من /payments أو من صفحة العميل أو من صفحة الفاتورة
         ↓
   اختيار العميل + المبلغ + وسيلة الدفع
         ↓
   POST /payments { customer_id, payment_method_id, amount }
         ↓
   customers.total_debt يُعاد حسابه تلقائياً


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 4: تسوية (المتجر مدين للعميل)                                        │
└─────────────────────────────────────────────────────────────────────────────┘

   total_debt < 0 (المتجر مدين للعميل)
         ↓
   من /settlements أو من صفحة العميل أو الفاتورة
         ↓
   اختيار العميل + المبلغ + وسيلة الرد
         ↓
   POST /settlements { customer_id, payment_method_id, amount }
         ↓
   customers.total_debt يُعاد حسابه تلقائياً


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 5: مرتجع — زبون نقدي                                                 │
└─────────────────────────────────────────────────────────────────────────────┘

   إنشاء سجل مرتجع + إضافة المنتجات
         ↓
   stock += quantity لكل سطر
         ↓
   تسوية تلقائية بقيمة المرتجع (دائماً)
         ↓
   customers.total_debt يُعاد حسابه


┌─────────────────────────────────────────────────────────────────────────────┐
│ تدفق 6: مرتجع — زبون مسجّل                                                │
└─────────────────────────────────────────────────────────────────────────────┘

   إنشاء سجل مرتجع + إضافة المنتجات
         ↓
   stock += quantity لكل سطر
         ↓
   النظام يحسب total_debt بعد الإرجاع
         ↓
   ┌─────────────────────────────────────────────────────┐
   │ total_debt بعد الإرجاع > 0                          │
   │   → لا تسوية — المرتجع يُخفّض الدين فقط            │
   ├─────────────────────────────────────────────────────┤
   │ total_debt بعد الإرجاع <= 0                         │
   │   → يظهر خيار: [إنشاء تسوية] [لاحقاً]              │
   └─────────────────────────────────────────────────────┘


================================================================================
                    🖥️ الصفحات

   /customers                  → قائمة العملاء + CRUD + دفعة/تسوية مباشرة

   /settlements/{id}           → تفاصيل تسوية + بيانات العميل + فاتورة مرتبطة
   /invoice-returns            → قائمة المرتجعات
   /invoice-returns/create     → إنشاء مرتجع جديد
   /invoice-returns/{id}       → تفاصيل مرتجع + أسطر + التسوية المرتبطة


================================================================================
                        ⚠️ قواعد العمل المهمة
================================================================================

📌 البيع:
1.  ✅ لا يمكن البيع إذا stock < الكمية المطلوبة
2.  ✅ unit_price يُسجَّل وقت البيع ولا يتغير (snapshot)
3.  ✅ price_vip <= unit_price <= price_regular (البائع يدخله ضمن المدى)
4.  ✅ stock -= quantity فور إضافة أي سطر للفاتورة
5.  ✅ حذف فاتورة → يُعاد مخزون جميع أسطرها
6.  ✅ حذف فاتورة → payments.invoice_id يصبح NULL (تبقى كسجل مالي)

📌 الدفع:
7.  ✅ زبون نقدي (id=1) → يجب الدفع الكامل فوراً
8.  ✅ زبون مسجّل → يمكن الدفع الجزئي أو المؤجل
9.  ✅ الدفعة تُخفّض total_debt للعميل
10. ✅ لا يمكن أن يتجاوز paid_amount قيمة total في فاتورة واحدة

📌 التسويات:
11. ✅ التسوية تُستخدم فقط عندما يكون total_debt < 0 (المتجر مدين)
12. ✅ التسوية تزيد total_debt (تُقلّص الدائنية)
13. ✅ لا يمكن إنشاء تسوية إذا كان total_debt > 0 (استخدم الدفعة)

📌 المرتجعات:
14. ✅ stock += quantity فور إضافة أي سطر مرتجع
15. ✅ حذف سطر مرتجع → stock -= quantity
16. ✅ حذف سجل المرتجع → يُعاد خصم مخزون كل الأسطر (CASCADE)
17. ✅ زبون نقدي → تسوية تلقائية دائماً بقيمة المرتجع
18. ✅ زبون مسجّل + total_debt بعد الإرجاع > 0 → لا تسوية
19. ✅ زبون مسجّل + total_debt بعد الإرجاع <= 0 → خيار إنشاء تسوية

📌 الحذف:
20. ✅ حذف invoice → يحذف invoice_items تلقائياً (CASCADE)
21. ✅ حذف invoice_return → يحذف invoice_return_items تلقائياً (CASCADE)


================================================================================
                    ⚙️ قواعد التحديث التلقائي (Observers)
================================================================================

كل تغيير في الجداول أدناه يُطلق Observer يحدّث الحقول المؤقتة تلقائياً.

┌─────────────────────────────────────────────────────────────────────────────┐
│ InvoiceItemObserver                                                         │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted / updated في invoice_items
يحدّث:
   invoices.total          = SUM(invoice_items.line_total)
   invoices.due_amount     = total - paid_amount
   invoices.payment_status = حسب القاعدة
   customers.total_purchases = SUM(invoices.total)
   customers.total_debt      = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ PaymentObserver                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted في payments
يحدّث:
   إذا invoice_id موجود:
      invoices.paid_amount    = SUM(payments.amount WHERE invoice_id)
      invoices.due_amount     = total - paid_amount
      invoices.payment_status = حسب القاعدة
   دائماً:
      customers.total_paid = SUM(payments.amount)
      customers.total_debt = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ SettlementObserver                                                          │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted في settlements
يحدّث:
   customers.total_settlements = SUM(settlements.amount)
   customers.total_debt        = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ InvoiceReturnItemObserver                                                   │
└─────────────────────────────────────────────────────────────────────────────┘
عند: created / deleted في invoice_return_items
يحدّث:
   invoice_returns.total      = SUM(invoice_return_items.line_total)
   customers.total_returns    = SUM(invoice_returns.total)
   customers.total_debt       = إعادة حساب


┌─────────────────────────────────────────────────────────────────────────────┐
│ معادلة total_debt للعميل                                              │
└─────────────────────────────────────────────────────────────────────────────┘

total_debt = total_purchases - total_paid + total_settlements - total_returns

قاعدة: customer_id = 1 (زبون نقدي) → لا يُحدَّث أي حقل مالي
