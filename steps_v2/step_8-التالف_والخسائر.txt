================================================================================
                    المرحلة 8: التالف والخسائر
================================================================================

📋 نظرة عامة:
--------------
التالف = خصم من المخزون بدون بيع.
كل منتج يمكن أن يتلف — عطور، بخور، وشق، مواد تشغيلية، ...
الهدف: تسجيل الخسائر، تحديث المخزون، وتتبع أسباب التلف.

📌 الفرق عن البيع والمشتريات:
   البيع:      مخزون ينقص + فاتورة + عميل + دفع
   المشتريات:  مخزون يزيد + فاتورة + مورد + دفع
   التالف:     مخزون ينقص + لا فاتورة + لا عميل + لا دفع


================================================================================
                    🗂️ الجداول الجديدة (جدولان)
================================================================================

   1. waste_logs    → رأس سجل التالف
   2. waste_items   → أسطر التالف (منتج + كمية + سبب)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 1️⃣  waste_logs                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

📌 الوظيفة:
   رأس سجل التالف — يجمع معلومات من سجّله ومتى.
   سجل واحد يمكن أن يحتوي على أكثر من منتج تالف.

الحقل          النوع           العلاقة          القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          PK               AUTO_INCREMENT        المعرف
user_id        BIGINT          FK → users.id    —                     من سجّل التالف
notes          TEXT            —                NULL                  ملاحظات عامة
created_at     TIMESTAMP       —                CURRENT_TIMESTAMP     تاريخ التسجيل
updated_at     TIMESTAMP       —                CURRENT_TIMESTAMP     تاريخ التحديث

Constraints:
   INDEX (user_id)
   INDEX (created_at)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 2️⃣  waste_items                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

📌 الوظيفة:
   سطر واحد لكل منتج تالف داخل السجل.
   عند إضافة السطر: products.stock -= quantity فوراً.
   يحفظ سبب التلف لكل منتج على حدة.

الحقل          النوع           العلاقة              القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          PK                   AUTO_INCREMENT        المعرف
waste_log_id   BIGINT          FK → waste_logs.id   —                     السجل
product_id     BIGINT          FK → products.id     —                     المنتج
quantity       DECIMAL(10,2)   —                    —                     الكمية التالفة
reason         ENUM            —                    'other'               سبب التلف
notes          TEXT            —                    NULL                  ملاحظة إضافية
created_at     TIMESTAMP       —                    CURRENT_TIMESTAMP     تاريخ الإنشاء

ENUM reason:
   'broken'    → كسر (عبوة مكسورة، زجاجة سقطت)
   'spilled'   → انسكاب
   'expired'   → انتهاء الصلاحية / فساد
   'lost'      → مفقود
   'other'     → سبب آخر

Constraints:
   FOREIGN KEY (waste_log_id) ON DELETE CASCADE
   INDEX (waste_log_id)
   INDEX (product_id)

📌 قاعدة خصم المخزون:
   عند إضافة سطر: products.stock -= quantity
   عند حذف سطر:   products.stock += quantity (إعادة)
   عند حذف السجل: يحذف جميع waste_items تلقائياً (CASCADE)
                   ويُعاد المخزون لكل سطر قبل الحذف

================================================================================
                    🖥️ تصميم صفحة الإنشاء (POS Style)
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ اللوحة اليسرى — إدخال المنتجات التالفة                                    │
└─────────────────────────────────────────────────────────────────────────────┘

   - اختيار المنتج (جميع المنتجات بما فيها التشغيلية)
   - الكمية التالفة
   - سبب التلف (broken / spilled / expired / lost / other)
   - ملاحظات (اختياري)
   - زر إضافة

┌─────────────────────────────────────────────────────────────────────────────┐
│ اللوحة اليمنى — سجل التالف                                                │
└─────────────────────────────────────────────────────────────────────────────┘

   - جدول المنتجات المضافة (المنتج + الكمية + السبب + حذف)
   - إجمالي عدد المنتجات التالفة
   - حقل ملاحظات عامة
   - زر تأكيد التسجيل

                    🔄 خطوات التنفيذ (بالترتيب)

┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 2: Models                                                            │
└─────────────────────────────────────────────────────────────────────────────┘

WasteLog  → fillable + علاقات (user, items)
WasteItem → fillable + علاقات (wasteLog, product)


┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 3: Repository + Controller                                           │
└─────────────────────────────────────────────────────────────────────────────┘

WasteRepository:
   - allWithRelations()
   - findWithRelations(id)
   - createLog(data)         → ينشئ waste_log
   - addItem(logId, data)    → ينشئ waste_item + stock -= quantity
   - updateItem(logId, itemId, data) → يعدّل waste_item + يصحح المخزون:
                                         diff = newQty - oldQty
                                         diff > 0 → stock -= diff
                                         diff < 0 → stock += abs(diff)
   - removeItem(logId, id)   → يحذف waste_item + stock += quantity

WasteController:
   - index()
   - create()
   - storeWithItems()        → ينشئ السجل + الأسطر دفعة واحدة
   - show(id)
   - addItem(id)
   - removeItem(id, itemId)
   - destroy(id)             → يُعيد المخزون ثم يحذف


┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 4: Routes                                                            │
└─────────────────────────────────────────────────────────────────────────────┘

Route::resource('waste', WasteController::class)->except(['edit']);
Route::post('waste/store-with-items', [WasteController::class, 'storeWithItems']);
Route::post('waste/{id}/items', [WasteController::class, 'addItem']);
Route::patch('waste/{id}/items/{itemId}', [WasteController::class, 'updateItem']);
Route::delete('waste/{id}/items/{itemId}', [WasteController::class, 'removeItem']);

================================================================================
                    📊 مثال سجل تالف كامل
================================================================================

السجل رقم: 1
المسجِّل: أحمد محمد
التاريخ: 2024-03-10
الملاحظات: كسر أثناء الترتيب

┌────┬──────────────────┬──────────┬──────────┬──────────────────┐
│ #  │ المنتج           │ الكمية   │ السبب    │ ملاحظة           │
├────┼──────────────────┼──────────┼──────────┼──────────────────┤
│ 1  │ Dior Sauvage     │ 50ml     │ كسر      │ زجاجة سقطت      │
│ 2  │ بخور عود         │ 20 pcs   │ فساد     │ تعرض للرطوبة     │
│ 3  │ كيسة             │ 50 pcs   │ مفقود    │ —                │
└────┴──────────────────┴──────────┴──────────┴──────────────────┘

النتيجة:
   Dior Sauvage: stock -= 50
   بخور عود:     stock -= 20
   كيسة:         stock -= 50


================================================================================
                        ⚠️ قواعد العمل المهمة
================================================================================

1. ✅ stock -= quantity فور إضافة أي سطر
2. ✅ لا يمكن تسجيل تالف أكثر من المخزون المتاح
3. ✅ حذف سطر → stock += quantity (إعادة المخزون)
4. ✅ حذف السجل كاملاً → يُعاد مخزون كل الأسطر قبل الحذف (CASCADE)
5. ✅ جميع المنتجات مؤهلة للتالف (بيعية + تشغيلية)
6. ✅ reason يُسجَّل لكل منتج على حدة (ليس للسجل كله)
7. ✅ user_id إلزامي — يجب معرفة من سجّل التالف


================================================================================
                        🎯 ما اكتمل بعد هذه المرحلة
================================================================================

✅ التالف مُسجَّل ومُتتبَّع بالكامل
✅ المخزون يُخصم تلقائياً عند كل تسجيل
✅ تاريخ كامل لأسباب التلف لكل منتج
✅ إمكانية إضافة أسطر جديدة لسجل موجود

❌ لم يُضف بعد:
   - التقارير والإحصائيات (مصاريف التالف، أكثر المنتجات تلفاً، ...)
