================================================================================
                    المرحلة 11: نظام التدوير (Period Rollover)
================================================================================

📋 نظرة عامة:
--------------
نظام التدوير يتيح إغلاق فترة محاسبية وفتح فترة جديدة نظيفة.
عند التدوير يتم:
   1. حفظ Snapshot كامل للأرصدة النهائية
   2. نقل الأرصدة الافتتاحية للفترة الجديدة
   3. مسح الجداول اليومية (فواتير، مشتريات، دفعات، ...)

📌 المبدأ الأساسي:
   الـ Snapshot = الحقيقة المالية النهائية لكل فترة
   الجداول اليومية = تفاصيل قابلة للمسح بعد التدوير
   المخزون = لا يُمسح، يبقى كما هو وينتقل تلقائياً


================================================================================
                    🗂️ الجداول الجديدة
================================================================================

   1. accounting_periods     → إدارة الفترات المحاسبية
   2. period_snapshots       → الأرصدة النهائية لكل فترة
   3. period_snapshot_items  → تفاصيل الـ Snapshot (عميل / مورد / منتج / خزينة)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 1️⃣  accounting_periods                                                      │
└─────────────────────────────────────────────────────────────────────────────┘

📌 الوظيفة:
   يحفظ معلومات كل فترة محاسبية (اسمها، تاريخ الفتح والإغلاق، حالتها).

الحقل          النوع           القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          AUTO_INCREMENT        المعرف
name           VARCHAR(100)    —                     اسم الفترة (مثل: 2025، Q1-2026)
started_at     TIMESTAMP       —                     تاريخ فتح الفترة
closed_at      TIMESTAMP       NULL                  تاريخ إغلاق الفترة
status         ENUM            'open'                حالة الفترة
notes          TEXT            NULL                  ملاحظات
created_by     BIGINT          FK → users.id         من أنشأ الفترة
created_at     TIMESTAMP       CURRENT_TIMESTAMP     —
updated_at     TIMESTAMP       CURRENT_TIMESTAMP     —

ENUM status:
   'open'    → الفترة الحالية النشطة (واحدة فقط في كل وقت)
   'closed'  → فترة مغلقة (تم تدويرها)

Constraints:
   INDEX (status)
   INDEX (started_at)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 2️⃣  period_snapshots                                                        │
└─────────────────────────────────────────────────────────────────────────────┘

📌 الوظيفة:
   رأس الـ Snapshot — يربط الأرصدة النهائية بفترة محددة.

الحقل          النوع           القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          AUTO_INCREMENT        المعرف
period_id      BIGINT          FK → accounting_periods.id   الفترة
snapshot_at    TIMESTAMP       CURRENT_TIMESTAMP     وقت أخذ الـ Snapshot
created_by     BIGINT          FK → users.id         من أجرى التدوير
notes          TEXT            NULL                  ملاحظات
created_at     TIMESTAMP       CURRENT_TIMESTAMP     —

Constraints:
   UNIQUE (period_id)   → snapshot واحد لكل فترة
   INDEX (period_id)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 3️⃣  period_snapshot_items                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

📌 الوظيفة:
   تفاصيل الـ Snapshot — رصيد كل عميل / مورد / منتج / وسيلة دفع.

الحقل          النوع           القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          AUTO_INCREMENT        المعرف
snapshot_id    BIGINT          FK → period_snapshots.id     الـ Snapshot
type           ENUM            —                     نوع الرصيد
entity_id      BIGINT          —                     معرف العميل / المورد / المنتج / وسيلة الدفع
entity_name    VARCHAR(255)    —                     الاسم (محفوظ للأرشفة)
balance        DECIMAL(15,2)   0                     الرصيد النهائي
created_at     TIMESTAMP       CURRENT_TIMESTAMP     —

ENUM type:
   'customer'        → دين العميل
   'supplier'        → دين المورد
   'product_stock'   → مخزون المنتج
   'payment_method'  → رصيد وسيلة الدفع (الخزينة)

Constraints:
   FOREIGN KEY (snapshot_id) ON DELETE CASCADE
   INDEX (snapshot_id)
   INDEX (type)
   INDEX (entity_id)


================================================================================
                    📌 حقل opening_balance في العملاء والموردين
================================================================================

📌 يُضاف حقل جديد لجدولي customers و suppliers:

   opening_balance   DECIMAL(15,2)   DEFAULT 0

📌 الوظيفة:
   يحفظ الرصيد الافتتاحي المنقول من الفترة السابقة.
   يُضاف إلى حساب الدين الحالي في كل التقارير.

📌 معادلة الدين الحقيقي بعد التدوير:
   الدين = opening_balance + (فواتير الفترة الحالية + تسويات) - (دفعات + مرتجعات)


================================================================================
                    🔁 خطوات التدوير (بالترتيب)
================================================================================

الخطوة 1: التحقق
   - لا توجد فترة مفتوحة أخرى
   - المستخدم لديه صلاحية super-admin

الخطوة 2: إنشاء Snapshot
   - حفظ دين كل عميل (opening_balance الحالي + حركات الفترة)
   - حفظ دين كل مورد
   - حفظ مخزون كل منتج
   - حفظ رصيد كل وسيلة دفع

الخطوة 3: نقل الأرصدة الافتتاحية
   - customers.opening_balance = الدين النهائي من الـ Snapshot
   - suppliers.opening_balance = الدين النهائي من الـ Snapshot

الخطوة 4: مسح الجداول اليومية
   - invoice_items       → مسح
   - invoices            → مسح
   - payments            → مسح
   - settlements         → مسح
   - purchase_items      → مسح
   - purchases           → مسح
   - supplier_payments   → مسح
   - supplier_settlements→ مسح
   - invoice_return_items→ مسح
   - invoice_returns     → مسح
   - purchase_return_items→ مسح
   - purchase_returns    → مسح
   - waste_items         → مسح
   - waste_logs          → مسح

الخطوة 5: إغلاق الفترة الحالية
   - accounting_periods.status = 'closed'
   - accounting_periods.closed_at = now()

الخطوة 6: فتح فترة جديدة
   - إنشاء سجل جديد في accounting_periods بـ status = 'open'

================================================================================
                    🖥️ تصميم صفحة التدوير
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ معاينة ما سيتم حفظه في الـ Snapshot                                        │
└─────────────────────────────────────────────────────────────────────────────┘

   - جدول ديون العملاء (الاسم + الرصيد النهائي)
   - جدول ديون الموردين (الاسم + الرصيد النهائي)
   - جدول المخزون (المنتج + الكمية)
   - جدول الخزينة (وسيلة الدفع + الرصيد)

┌─────────────────────────────────────────────────────────────────────────────┐
│ تأكيد التدوير                                                               │
└─────────────────────────────────────────────────────────────────────────────┘

   - اسم الفترة الجديدة (input)
   - ملاحظات (textarea)
   - زر "تنفيذ التدوير" (يطلب تأكيد مزدوج)

⚠️ تحذير واضح:
   "سيتم مسح جميع الفواتير والمشتريات والدفعات للفترة الحالية بشكل نهائي.
    تأكد من حفظ التقارير قبل المتابعة."

┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 2: Models                                                            │
└─────────────────────────────────────────────────────────────────────────────┘

AccountingPeriod   → fillable + علاقات (snapshots, createdBy)
PeriodSnapshot     → fillable + علاقات (period, items, createdBy)
PeriodSnapshotItem → fillable + علاقات (snapshot)

┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 3: Repository + Service                                              │
└─────────────────────────────────────────────────────────────────────────────┘

RolloverService:
   - previewSnapshot()     → يحسب الأرصدة بدون حفظ (للمعاينة)
   - executeRollover(data) → ينفذ كل خطوات التدوير في Transaction واحدة
   - getSnapshotDetails(periodId) → يجلب تفاصيل Snapshot فترة محددة

┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 4: Controller                                                        │
└─────────────────────────────────────────────────────────────────────────────┘

PeriodController:
   - index()    → قائمة الفترات
   - rollover() → صفحة التدوير مع المعاينة
   - execute()  → تنفيذ التدوير
   - snapshot() → عرض تفاصيل Snapshot

┌─────────────────────────────────────────────────────────────────────────────┐
│ الخطوة 5: Routes                                                            │
└─────────────────────────────────────────────────────────────────────────────┘

    Route::get('periods',                [PeriodController::class, 'index']);
    Route::get('periods/rollover',       [PeriodController::class, 'rollover']);

    Route::get('periods/{id}/snapshot',  [PeriodController::class, 'snapshot']);
});

================================================================================
                    ⚠️ قواعد العمل المهمة
================================================================================

1.  ✅ فترة واحدة فقط بحالة 'open' في أي وقت
2.  ✅ التدوير يتم داخل DB Transaction — إما كل شيء أو لا شيء
3.  ✅ الـ Snapshot يُحفظ قبل أي مسح
4.  ✅ opening_balance يُحدَّث بعد حفظ الـ Snapshot مباشرة
5.  ✅ المسح يتم بعد التأكد من نجاح الـ Snapshot والـ opening_balance
6.  ✅ المخزون لا يُمسح — يبقى كما هو في products.stock
7.  ✅ الصلاحية: super-admin فقط
8.  ✅ لا يمكن التراجع عن التدوير بعد تنفيذه
9.  ✅ التقارير تأخذ opening_balance بعين الاعتبار في حساب الديون
10. ✅ entity_name يُحفظ في الـ Snapshot لضمان بقاء الاسم حتى لو تغيّر لاحقاً


================================================================================
                    📊 مثال تدوير كامل
================================================================================

الفترة: 2025
التاريخ: 2025-12-31

Snapshot المحفوظ:
┌──────────────────┬──────────────┬──────────────┐
│ النوع            │ الاسم        │ الرصيد       │
├──────────────────┼──────────────┼──────────────┤
│ customer         │ عميل نفخ     │ 270.00       │
│ supplier         │ مورد العطور  │ 1500.00      │
│ product_stock    │ Dior Sauvage │ 45 (وحدة)    │
│ payment_method   │ نقدي         │ 8500.00      │
│ payment_method   │ بطاقة        │ 3200.00      │
└──────────────────┴──────────────┴──────────────┘

بعد التدوير:
   - customers.opening_balance (عميل نفخ) = 270.00
   - suppliers.opening_balance (مورد العطور) = 1500.00
   - products.stock (Dior Sauvage) = 45 (لم يتغير)
   - جميع الفواتير والمشتريات والدفعات → محذوفة
   - فترة جديدة 2026 → مفتوحة
