================================================================================
                    المرحلة 11: نظام التدوير (Period Rollover)
================================================================================

📋 نظرة عامة:
--------------
نظام التدوير يتيح إغلاق فترة محاسبية وفتح فترة جديدة نظيفة.
التصميم يعتمد على إضافة period_id لكل الجداول اليومية بدل جداول Archive منفصلة.

📌 المبدأ الأساسي:
   كل سجل يأخذ period_id من لحظة إنشائه تلقائياً
   البيانات القديمة تبقى في نفس الجداول بـ period_id القديم
   الفترة الجديدة تعمل على period_id جديد — لا نقل ولا مسح
   Snapshot = الأرصدة النهائية + الملخص الإحصائي لكل فترة


================================================================================
                    🗂️ التغييرات على الجداول
================================================================================

📌 جداول جديدة (3 فقط):
   1. accounting_periods      → إدارة الفترات المحاسبية
   2. period_snapshots        → رأس الـ Snapshot لكل فترة
   3. period_snapshot_items   → تفاصيل الـ Snapshot

📌 حقل period_id يُضاف لكل الجداول اليومية:
   invoices.period_id
   invoice_items.period_id
   payments.period_id
   settlements.period_id
   purchases.period_id
   purchase_items.period_id
   supplier_payments.period_id
   supplier_settlements.period_id
   invoice_returns.period_id
   invoice_return_items.period_id
   purchase_returns.period_id
   purchase_return_items.period_id
   waste_logs.period_id
   waste_items.period_id

📌 حقل يُضاف لجداول العملاء والموردين:
   customers.opening_balance   DECIMAL(15,2)   DEFAULT 0
   suppliers.opening_balance   DECIMAL(15,2)   DEFAULT 0


================================================================================
                    🗂️ تفاصيل الجداول الجديدة
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ 1️⃣  accounting_periods                                                      │
└─────────────────────────────────────────────────────────────────────────────┘

الحقل          النوع           القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          AUTO_INCREMENT        المعرف
name           VARCHAR(100)    —                     اسم الفترة (مثل: 2025، Q1-2026)
started_at     TIMESTAMP       —                     تاريخ فتح الفترة
closed_at      TIMESTAMP       NULL                  تاريخ إغلاق الفترة
status         ENUM            'open'                حالة الفترة
notes          TEXT            NULL                  ملاحظات
created_by     BIGINT          FK → users.id         من أنشأ الفترة
created_at     TIMESTAMP       CURRENT_TIMESTAMP     —
updated_at     TIMESTAMP       CURRENT_TIMESTAMP     —

ENUM status:
   'open'    → الفترة الحالية النشطة (واحدة فقط في كل وقت)
   'closed'  → فترة مغلقة (تم تدويرها)

Constraints:
   INDEX (status)
   INDEX (started_at)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 2️⃣  period_snapshots                                                        │
└─────────────────────────────────────────────────────────────────────────────┘

الحقل          النوع           القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          AUTO_INCREMENT        المعرف
period_id      BIGINT          FK → accounting_periods.id   الفترة
snapshot_at    TIMESTAMP       CURRENT_TIMESTAMP     وقت أخذ الـ Snapshot
created_by     BIGINT          FK → users.id         من أجرى التدوير
notes          TEXT            NULL                  ملاحظات
created_at     TIMESTAMP       CURRENT_TIMESTAMP     —

Constraints:
   UNIQUE (period_id)
   INDEX (period_id)


┌─────────────────────────────────────────────────────────────────────────────┐
│ 3️⃣  period_snapshot_items                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

الحقل          النوع           القيمة الافتراضية    الوصف
──────────────────────────────────────────────────────────────────────────────
id             BIGINT          AUTO_INCREMENT        المعرف
snapshot_id    BIGINT          FK → period_snapshots.id     الـ Snapshot
type           ENUM            —                     نوع البيانات
entity_id      BIGINT          NULL                  معرف العميل/المورد/المنتج/وسيلة الدفع
entity_name    VARCHAR(255)    NULL                  الاسم (محفوظ للأرشفة)
balance        DECIMAL(15,2)   0                     الرصيد أو القيمة الإحصائية
created_at     TIMESTAMP       CURRENT_TIMESTAMP     —

ENUM type — أرصدة انتقالية (تنتقل للفترة الجديدة):
   'customer'            → دين العميل          (entity_id = customer.id)
   'supplier'            → دين المورد          (entity_id = supplier.id)
   'product_stock'       → مخزون المنتج        (entity_id = product.id)
   'payment_method'      → رصيد وسيلة الدفع    (entity_id = payment_method.id)

ENUM type — ملخص إحصائي (يبقى بعد Purge):
   'total_sales'         → إجمالي المبيعات     (entity_id = NULL)
   'total_purchases'     → إجمالي المشتريات    (entity_id = NULL)
   'total_returns_in'    → إجمالي مرتجعات العملاء
   'total_returns_out'   → إجمالي مرتجعات الموردين
   'total_waste'         → إجمالي التالف بالقيمة
   'total_paid_in'       → إجمالي الدفعات المقبوضة
   'total_paid_out'      → إجمالي الدفعات للموردين
   'invoices_count'      → عدد الفواتير
   'purchases_count'     → عدد فواتير الشراء
   'new_customers'       → عدد العملاء الجدد في الفترة

📌 للأنواع الإحصائية: entity_id = NULL، entity_name = NULL، balance = القيمة

Constraints:
   FOREIGN KEY (snapshot_id) ON DELETE CASCADE
   INDEX (snapshot_id, type)
   INDEX (entity_id)


================================================================================
                    🔄 كيف يعمل period_id
================================================================================

📌 كل سجل يأخذ period_id من لحظة إنشائه:

   // عند إنشاء أي سجل
   $invoice = Invoice::create([
       'period_id' => getCurrentPeriodId(), // الفترة المفتوحة حالياً
       'total'     => ...,
   ]);

   getCurrentPeriodId() = AccountingPeriod::where('status', 'open')->value('id')

📌 لا يوجد أي تحديث أو نقل عند التدوير — كل سجل يحمل period_id منذ إنشائه.

📌 الاستعلام حسب الفترة:

   -- بيانات الفترة الحالية فقط
   WHERE period_id = 2

   -- بيانات فترة قديمة
   WHERE period_id = 1

   -- كل البيانات (كل الفترات)
   WHERE created_at BETWEEN ? AND ?

   -- فترات متعددة
   WHERE period_id IN (1, 2, 3)


================================================================================
                    🔁 خطوات التدوير (بالترتيب)
================================================================================

الخطوة 1: التحقق
   - فترة واحدة فقط بحالة 'open'
   - المستخدم لديه صلاحية super-admin

الخطوة 2: إنشاء Snapshot
   أ) أرصدة انتقالية:
      - حفظ دين كل عميل  (opening_balance + حركات الفترة الحالية)
      - حفظ دين كل مورد
      - حفظ مخزون كل منتج
      - حفظ رصيد كل وسيلة دفع

   ب) ملخص إحصائي للفترة:
      - total_sales      = SUM(invoices.total WHERE period_id = current)
      - total_purchases  = SUM(purchases.total WHERE period_id = current)
      - total_returns_in = SUM(invoice_returns.total WHERE period_id = current)
      - total_returns_out= SUM(purchase_returns.total WHERE period_id = current)
      - total_waste      = SUM(waste_items.quantity * آخر سعر شراء)
      - total_paid_in    = SUM(payments.amount WHERE period_id = current)
      - total_paid_out   = SUM(supplier_payments.amount WHERE period_id = current)
      - invoices_count   = COUNT(invoices WHERE period_id = current)
      - purchases_count  = COUNT(purchases WHERE period_id = current)
      - new_customers    = COUNT(customers WHERE created_at في الفترة)

الخطوة 3: تحديث الأرصدة الافتتاحية
   customers.opening_balance = الدين النهائي من الـ Snapshot
   suppliers.opening_balance = الدين النهائي من الـ Snapshot

الخطوة 4: إغلاق الفترة الحالية
   accounting_periods.status    = 'closed'
   accounting_periods.closed_at = now()

الخطوة 5: فتح فترة جديدة
   INSERT INTO accounting_periods (name, started_at, status, created_by)

⚠️ كل هذه الخطوات تتم داخل DB Transaction واحدة — إما كل شيء أو لا شيء.
⚠️ لا يوجد نقل بيانات ولا مسح — فقط Snapshot + إغلاق + فتح.


================================================================================
                    🗑️ Purge (اختياري)
================================================================================

📌 حذف بيانات فترة قديمة (بعد التأكد من وجود Snapshot):

   DELETE FROM invoices          WHERE period_id = {id}
   DELETE FROM invoice_items     WHERE period_id = {id}
   DELETE FROM payments          WHERE period_id = {id}
   DELETE FROM settlements       WHERE period_id = {id}
   DELETE FROM purchases         WHERE period_id = {id}
   DELETE FROM purchase_items    WHERE period_id = {id}
   DELETE FROM supplier_payments WHERE period_id = {id}
   DELETE FROM supplier_settlements WHERE period_id = {id}
   DELETE FROM invoice_returns   WHERE period_id = {id}
   DELETE FROM invoice_return_items WHERE period_id = {id}
   DELETE FROM purchase_returns  WHERE period_id = {id}
   DELETE FROM purchase_return_items WHERE period_id = {id}
   DELETE FROM waste_logs        WHERE period_id = {id}
   DELETE FROM waste_items       WHERE period_id = {id}

📌 Auto-Purge للفترات الأقدم من X سنة:
   $old = AccountingPeriod::where('closed_at', '<', now()->subYears(2))->get();
   // حذف بيانات كل فترة قديمة — الـ Snapshot يبقى دائماً

📌 قاعدة ذهبية:
   الـ Snapshot لا يُحذف أبداً — حتى بعد Purge.
   الـ Snapshot = السجل المالي الدائم للفترة.


================================================================================
                    📊 التقارير
================================================================================

📌 التقارير تعمل على نفس الجداول — فقط تتغير الفلترة:

   -- الفترة الحالية فقط (الافتراضي)
   Invoice::where('period_id', getCurrentPeriodId())->...

   -- فترة محددة
   Invoice::where('period_id', $periodId)->...

   -- نطاق تاريخي (يشمل كل الفترات تلقائياً)
   Invoice::whereBetween('created_at', [$from, $to])->...

   -- كل الفترات
   Invoice::all()->...

📌 لا UNION ALL — نفس الجدول، نفس الـ Query، فقط period_id يتغير.

📌 تقارير ديون العملاء بعد التدوير:
   الدين = customers.opening_balance
         + (فواتير الفترة الحالية + تسويات)
         - (دفعات + مرتجعات)

                    📊 مثال تدوير كامل
